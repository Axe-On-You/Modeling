## Исследуемые системы

В обеих системах общий входной поток пуассоновский с интенсивностью **0.6 заявки/с**, среднее обслуживание в каждом приборе — **5 с**. При заполненном выбранном узле заявка теряется; перенаправления к другим приборам нет.

| Параметр | Система 1, вариант 33 | Система 2, вариант 73 |
|---|---|---|
| Число приборов | 2 | 3 |
| Места ожидания перед приборами | 2 / 1 | 1 / 0 / 1 |
| Интенсивности входных потоков | 0.45 / 0.15 | 0.45 / 0.12 / 0.03 |
| Обслуживание | Экспоненциальное в обоих приборах | Эрланга E₂ только в П1; экспоненциальное в П2 и П3 |
| Интенсивность обслуживания | μ = 0.2 | μ = 0.2; интенсивность каждой из двух последовательных фаз П1 — ν = 0.4 |
| Число состояний полной модели | 12 | 30 |

Времена ожидания и пребывания рассчитываются через вероятности состояний и остаточные фазы обслуживания. Формулы Литтла используются для последующей проверки.

В WinMark выполнен расчёт исходной точки и 40 точек варьирования общей интенсивности от 0.05 до 2.00 с шагом 0.05. Для каждой системы экспортированы графики загрузки, производительности, потерь, длины очереди, времени ожидания и времени пребывания.

## Независимый расчёт

Требуется **Python 3.10 или новее**. Сторонние библиотеки не нужны.

Из папки `Лабораторная 2`:

```bash
python app/calculate_uir2.py
```

Скрипт автоматически создаёт папку `out/` и сохраняет в ней `results.json` и `calculation_log.txt`. Пути определяются относительно расположения самого скрипта, поэтому результат не зависит от рабочей папки терминала или PyCharm. Рассчитываются полные модели, все характеристики, 40 точек нагрузки и контрольные эксперименты с накопителем и выбором прибора для E₂.

Сверка экспортов запускается из корня лабораторной:

```bash
python docs/verify_winmark.py
```

Проверяются 56 характеристик и 42 вероятности в исходной точке, а также 2240 значений характеристик и 1680 вероятностей при варьировании. Скрипт автоматически сохраняет `docs/winmark_verification.json` и `docs/winmark_verification.txt` и завершает проверку сообщением `PASS`, если проверки пройдены. Он загружает расчётный модуль из `app/` и HTML-отчёты из `docs/system1/` и `docs/system2/` независимо от рабочей папки.

## Работа в WinMark

1. Запустить `WinMark/WinMark.exe` в Windows.
2. Через **«Файл → Загрузить…»** открыть нужную модель из `WinMark/out/`.
3. Выполнить **«Расчёт → Вероятности…»**, затем **«Расчёт → Формулы…»**.
4. Для исследования нагрузки использовать **«Данные → Варьируемые элементы…»** и **«Расчёт → Варьирование…»**.

Полные результаты доступны в `docs/system1/report_system1.html` и `docs/system2/report_system2.html`; для просмотра достаточно открыть их браузером вместе с папками изображений. На исходных JPG WinMark горизонтальная ось показывает индекс `j = 0…39`: общая интенсивность равна `0.05 × (j + 1)`.

Перед повторным экспортом исходной точки нужно восстановить исходные элементы и пересчитать вероятности и формулы. Варьирование непосредственно перед экспортом повторно не запускается, чтобы значения в точке относились к исходной нагрузке.

## Сборка отчёта

Нужен TeX Live или MiKTeX с **XeLaTeX**. Из корня лабораторной:

```bash
cd docs
xelatex -interaction=nonstopmode -halt-on-error UIR2_Mikhailov_33-73-11.tex
xelatex -interaction=nonstopmode -halt-on-error UIR2_Mikhailov_33-73-11.tex
cd ..
```

Двойная сборка обновляет оглавление и ссылки. Для Overleaf следует загрузить папку лабораторной с сохранением структуры, выбрать главным документом файл из `docs/` и указать XeLaTeX.

## Результат

При исходной интенсивности первая система лучше по заданному критерию: суммарная загрузка **1.516814** против **1.432517**. Её производительность — **0.303363** против **0.286503 заявки/с**. Вторая система обеспечивает меньшее среднее время пребывания: **7.145069** против **10.460153 с**.

Дополнительная проверка всех трёх допустимых размещений E₂ во второй системе сохраняет выбор первой системы при исходной нагрузке. Для основного размещения E₂ в П1 преимущество по суммарной загрузке меняется около интенсивности **1.083188 заявки/с**.
